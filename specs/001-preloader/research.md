# Research: Прелоадер лендинга CPA

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-11-09

## R1. Что считать «первым успешным ответом API для текущего языка»

- **Decision**: прелоадер ждёт успешные ответы всех трёх секций текущего языка — `benefits`, `tasks`, `multiply` (`getContent(lang, section)`).
- **Rationale**: отдельного «языкового» эндпоинта нет, данные берутся тремя запросами. Секции рисуют контент только после загрузки данных, а секция `#join` (`MultiplyWithUs`) вообще появляется в DOM только с данными. Если ждать один запрос, после исчезновения прелоадера остальные секции на мгновение показывают состояние загрузки (нарушение SC-003), а якорь `/ru#join` некуда прокручивать (FR-012). Когда сервер проснулся, три запроса укладываются в доли секунды, лишнего ожидания нет.
- **Alternatives considered**: ждать один любой запрос — быстрее на долю секунды, но ломает SC-003 и FR-012; добавить на бэкенд эндпоинт «пинг» — вне рамок фронтенда.

## R2. Как не делать запросы дважды (прелоадер и секции)

- **Decision**: в `shared/api` появляется кэш промисов контента по ключу `${lang}/${section}` и функция `prefetchContent(lang, signal)`. `useContent` сначала смотрит в кэш: если данные уже есть, сразу возвращает их с `loading: false`. Промис, завершившийся ошибкой, удаляется из кэша, чтобы повтор сделал новый запрос.
- **Rationale**: секции после исчезновения прелоадера получают данные синхронно с первого рендера, без мигания состояния загрузки и без повторных запросов к только что проснувшемуся серверу. Смена языка работает как раньше: для нового языка `useContent` делает запрос сам, прелоадер не нужен (FR-013).
- **Alternatives considered**: подключить React Query/SWR — новая зависимость ради одного сценария; поднять данные в контекст на уровне `Home` — переписывает все три секции.

## R3. Повторы до истечения 60 секунд и отмена запросов

- **Decision**: ошибка любого из трёх запросов до дедлайна → новая попытка через 3 секунды. Дедлайн 60 секунд отсчитывается от монтирования прелоадера и заново от каждого нажатия «Повторить». На дедлайне висящие запросы отменяются через `AbortController`: в `request` добавляется необязательный `signal`.
- **Rationale**: при холодном старте сервер может как держать запрос открытым 30–40 секунд, так и отвечать 502/503, пока просыпается. Оба случая до 60 секунд выглядят для посетителя как обычная загрузка (FR-015). Отмена нужна, чтобы «зависший» запрос не завершился уже после показа ошибки.
- **Alternatives considered**: показывать ошибку на первом же неуспешном ответе — ложные ошибки при каждом холодном старте; экспоненциальная задержка — избыточно для окна в 60 секунд.

## R4. Ресурсы первого экрана

- **Decision**: ждать `document.fonts.ready` и загрузку изображений первого экрана (сейчас это `@public/img/snake-hero.png`). Список изображений передаёт страница `Home` пропсом, потому что знание о составе первого экрана — это уровень страницы. Ошибка загрузки изображения считается «готово», чтобы битая картинка не держала прелоадер вечно. Логотип — inline SVG, его ждать не нужно.
- **Rationale**: соответствует FR-002 и Assumptions спеки; прелоадер остаётся независимым от конкретных секций.
- **Alternatives considered**: импортировать картинку Hero прямо в виджет — виджет начинает зависеть от состава страницы; ждать `window.load` — ждёт все картинки всех секций, лишнее время.

## R5. Кривая прогресса и монотонность (GSAP)

- **Decision**: одно числовое значение прогресса в прокси-объекте `{ value }`, которое анимирует GSAP.
  - Фаза ожидания: твин `value → 90` с длительностью ~40 с и ease `power3.out` — быстро в начале, сильное замедление у 90%.
  - Фаза завершения: твин ожидания убивается, новый твин `value → 100` за 0,4 с, затем растворение прелоадера за 0,3 с, затем размонтирование.
  - Минимум 1 секунда (FR-008): фаза завершения не начинается раньше 0,6 с от показа, так что 0,6 + 0,4 = 1 с до начала растворения.
  - Число и линия обновляются в `onUpdate` напрямую через ref (текст `Math.round(value)%` и ширина заполнения), без React-ререндера на каждый кадр.
  - Повтор после ошибки не сбрасывает `value`: новый твин ожидания продолжает от текущего значения к 90 (FR-006, FR-015a).
- **Rationale**: одно значение — один источник правды для линии и числа (FR-004a, SC-002); значение только растёт, потому что все твины идут вверх.
- **Alternatives considered**: CSS-анимация — сложно остановить и продолжить с текущей точки; `scaleX` для заполнения — искажает скруглённые края из макета, поэтому анимируется ширина маленького элемента (дёшево).

## R6. Первый кадр до загрузки JavaScript

- **Decision**: в `src/index.html` добавляется статичная «оболочка» прелоадера: тот же градиент, что у `Background` (`linear-gradient(111deg, #DC8400 -5%, #560080 50%, #220032 95%)`), «0%» и пустая дорожка, стили инлайн. На ширине до 576px оболочка скрыта медиазапросом. React-прелоадер при монтировании удаляет оболочку; на mobile её удаляет `Home`. Шрифт числа подгружается заранее через `<link rel="preload">`.
- **Rationale**: без оболочки первые сотни миллисекунд, пока грузится бандл, посетитель видит пустой экран — нарушение FR-001 и SC-001.
- **Alternatives considered**: только фон на `body` — пустой градиент без индикатора тоже выглядит как «ничего не происходит».

## R7. Как прелоадер закрывает страницу

- **Decision**: прелоадер — фиксированный прозрачный слой поверх существующего `Background` (макет совпадает с фоном сайта: тот же градиент и сетка справа сверху). Логотип прелоадера стоит в той же позиции, что логотип шапки. Шапка и секции, пока прелоадер активен, обёрнуты в контейнер с `visibility: hidden`. Прокрутка блокируется `overflow: hidden` на `html` на время показа.
- **Rationale**: `visibility: hidden` одновременно убирает контент с экрана, отключает клики и фокус с клавиатуры (FR-010), а стартовая анимация первого экрана начинается только при показе (FR-009). Фон не дублируется, анимация сетки не копируется.
- **Alternatives considered**: непрозрачный слой со своей копией фона — дублирование `Background` и его GSAP-анимации; `inert` без скрытия — контент виден до готовности данных.

## R8. Lighthouse (SC-006)

- **Decision**: проверять Lighthouse desktop на `yarn build && yarn preview` при прогретом сервере. Ожидаемое влияние: LCP сдвигается на время показа прелоадера (минимум ~1,3 с: 1 с + растворение), потому что первый экран рисуется только после его исчезновения.
- **Rationale**: порог Performance ≥ 75 по constitution оставляет запас под такой сдвиг. Если порог не проходит — первым делом сокращается растворение и фаза завершения.
- **Alternatives considered**: рисовать первый экран под непрозрачным слоем ради раннего LCP — конфликтует с R7 и FR-009.

## R9. Анимации и constitution (принцип IV)

- **Decision**: все твины прелоадера создаются внутри `gsap.context()` и отменяются через `ctx.revert()` при размонтировании. Для `prefers-reduced-motion: reduce` длительности сводятся к нулю (линия меняется ступенями, без растворения). Смена ширины экрана анимацию не уничтожает: решение показывать прелоадер фиксируется в момент открытия (Edge Cases спеки). Отступление от принципа IV обосновано в Complexity Tracking.
- **Rationale**: `ctx.revert()` также корректно переживает двойной монтаж `StrictMode` в dev.
- **Alternatives considered**: `gsap.matchMedia()` по ширине — убил бы анимацию при повороте/ресайзе посреди загрузки.

## R10. Языки

- **Decision**: прелоадер работает только с языками, которые уже есть в `LANGUAGES` (`src/shared/config/languages.ts`): en и ru. Список языков в этой фиче не меняется. Тексты прелоадера типизированы как `Record<Lang, PreloaderTexts>`.
- **Rationale**: тип через `Lang` гарантирует, что тексты есть для каждого языка проекта (принцип II); если позже язык добавят, TypeScript сам потребует для него тексты прелоадера.
- **Alternatives considered**: отдельный список языков для прелоадера — может разойтись с `LANGUAGES`.

## R11. Тестирование

- **Decision**: автоматических тестов не добавляем; в проекте нет тестового фреймворка, constitution их не требует. Проверка — ручные сценарии из [quickstart.md](./quickstart.md) с DevTools (троттлинг, блокировка запросов), плюс ESLint и сборка.
- **Alternatives considered**: подключить Vitest + Testing Library ради хука состояния — отдельное решение для всего проекта, вне рамок фичи.
