# Snake (лендинг CPA) Constitution

## Core Principles

### I. Упрощённая FSD

- Код MUST быть разложен по слоям `app`, `pages`, `widgets`, `shared`; слой `features` не используется.
- Импорты MUST идти только сверху вниз: `app` → `pages` → `widgets` → `shared`.
- `shared` MUST NOT импортировать из `widgets`, `pages` или `app`.
- Циклические зависимости между модулями MUST NOT существовать.

**Rationale**: однонаправленные зависимости держат проект предсказуемым и позволяют
менять верхние слои, не ломая нижние.

### II. Мультиязычность

- Сайт MUST поддерживать языки из `LANGUAGES` (`src/shared/config/languages.ts`), сейчас en и ru:
  `/` (перенаправляет на `/en`), `/en`, `/ru`.
- Все тексты интерфейса MUST проходить через механизм i18n и MUST существовать для каждого
  поддерживаемого языка.
- Компоненты MUST NOT содержать проверок текущего языка (ветвлений вида «если ru, то …»);
  различия между языками живут только в данных i18n.

**Rationale**: добавление языка или правка текста не должны требовать правок в компонентах.

### III. Чистый код и линтеры

- Итоговый код MUST NOT содержать комментариев и вызовов `console.log`.
- ESLint и Stylelint MUST проходить без ошибок перед слиянием в `main`.

**Rationale**: код читается сам по себе, а линтеры ловят ошибки до ревью.

### IV. Анимации GSAP

- Каждая GSAP-анимация MUST уничтожаться при размонтировании компонента, при смене языка
  и при смене responsive-состояния.
- Хуки анимаций и любая другая логика MUST лежать в `src/shared/lib` и экспортироваться через
  `src/shared/lib/index.ts`; константы — в `src/shared/config`, переиспользуемые компоненты —
  в `src/shared/ui`. Папки `src/pages/*` MUST содержать только страницы и их стили.
- На mobile (ширина экрана до 576px) MUST быть отключены все анимации, кроме бегущей и
  переключающейся строк.

**Rationale**: неуничтоженные анимации дают утечки памяти и «призрачные» эффекты после смены
языка или ширины экрана; на mobile анимации ухудшают производительность.

### V. Соответствие макету и доступность

- Размеры текстов и элементов MUST совпадать с макетом.
- Для размеров MUST использоваться только единицы `px`, `rem`, `em`, `%`.
- Все интерактивные элементы MUST быть доступны с клавиатуры.

**Rationale**: вёрстка проверяется по макету один к одному, а сайт должен быть доступен
посетителям без мыши.

## Безопасность и производительность

- Секреты и ключи API MUST браться только из `.env`; в репозитории MUST лежать только
  `.env.example` без значений.
- Lighthouse на desktop MUST показывать: Performance не ниже 75; Accessibility,
  Best Practices и SEO не ниже 90.

## Стек и проверки качества

- Стек: React, TypeScript, Vite, SCSS Modules, GSAP.
- Перед слиянием в `main` MUST выполняться: ESLint без ошибок, Stylelint без ошибок,
  успешная сборка (`yarn build`), Lighthouse на desktop не ниже порогов из раздела
  «Безопасность и производительность».

## Governance

- Constitution имеет приоритет над остальными договорённостями проекта.
- Изменения вносятся через `/speckit-constitution` с обновлением версии и даты.
- Версии по semver: MAJOR — удаление или переопределение принципа; MINOR — новый принцип
  или раздел; PATCH — уточнения формулировок.
- Каждый план (`/speckit-plan`) и каждый PR MUST проверяться на соответствие принципам;
  отступление допускается только с письменным обоснованием в плане.
